Decoding understands all numeric entities (like &#233; and &#xE9;) and the most common named ones. Rare named entities are left unchanged. Entities must end with a semicolon.

How to use the HTML Entities Encoder and Decoder

  1. Type or paste your text or HTML into the Input box.
  2. Choose the Encode mode. Basic only changes the five special characters, and the other two modes also change non-English characters.
  3. Press Encode to turn characters into entities, or Decode to turn entities back into characters.
  4. Press Copy result to copy the output, or Swap to use it as the new input.

About this tool

Some characters have a special meaning in HTML. The signs < and & start tags and entities, so to show them as normal text you write them as &lt; and &amp;. These codes are called HTML entities. This tool converts text to entities and back in your browser, so nothing is uploaded.

Frequently asked questions

Which characters does Basic mode change?

Five characters: the ampersand &, the signs < and >, the double quote, and the single quote. They become &amp;, &lt;, &gt;, &quot; and &#39;.

What is the difference between numbers and names?

Both show the same character. For example, &eacute; and &#233; both show é. Names are easier to read, and numbers work for every character, including emoji. In the names mode, a number is used when a character has no known name.

Does it decode every named entity?

It decodes all numeric entities, written in decimal like &#233; or in hex like &#xE9;, and 198 of the most common named ones. A rare name is left unchanged.

Why is &amp without a semicolon not decoded?

The tool only decodes entities that end with a semicolon, such as &amp;. Text without the semicolon stays as it is.

What happens when I decode twice?

Each press decodes one level. If your text was encoded twice, for example &amp;lt;, the first press gives &lt; and the second press gives the sign <.

Does encoding make my page safe from attacks?

Encoding user text before you show it in HTML is an important part of preventing cross-site scripting (XSS). But safety also depends on where the text is placed, so use the escaping built into your framework or template engine rather than doing it by hand.
